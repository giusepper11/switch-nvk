## Allocation and lifetime gate

The selector-gated reservation is primary root `0x800`, primary QMD `0x100`, secondary QMD `0x100`,
then alternate root `0x800`. With the established alignment it occupies `0x1200` (4,608) bytes in
the existing 64-KiB upload BO, preserves QMD offsets `0x800`/`0x900`, places alternate root at
`0xa00`, and leaves `0xee00` (60,928) bytes. The maximum incremental live reservation versus the
fresh-QMD control is 2,048 bytes. Existing command-buffer ownership persists through submit/wait;
reset returns upload memory to the pool, and pool destruction performs final cleanup. No retained
64-allocation list or additional BO policy was added.

## Selectors and correlation

Build selectors `ROOT_ADDRESS_CONTROL=1` and `ROOT_ADDRESS_FRESH=1` forward only exact runtime values
`NVK_ROOT_ADDRESS_CONTROL=1` and `NVK_ROOT_ADDRESS_FRESH=1`. They are mutually exclusive and exclude
root-cache, QMD identity/cache, and QMD-address selectors. Absent/zero leaves the ordinary
one-root/one-QMD path unchanged. Both arms reserve/copy both roots and alternate QMD slots; control
selects primary root for all records, while fresh selects primary/alternate on odd/even records.

All 64 records perform complete root source/primary/alternate comparisons, selected QMD source/map
comparison, layout-derived root-address decoding, and complete QMD equality outside the union of the
layout-provided root address fields. Hashes are labels only. The selected QMD VA is correlated to
direct `PCAS`. CPU-mapped equality is explicitly recorded as `gpu_visible=UNPROVEN`.
